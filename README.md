# FindingCoordinates

指定時間 A（各城市當地日期時間），以 B 為基準，查詢未來 60 分鐘內會到達 A 的內建城市與座標。

## 使用方式

1. 開啟 `index.html`，輸入 A，例如 `20260923 11:00`。
2. B 可選「目前台灣時間」或手動輸入台灣時間，例如 `20260923 09:53`。
3. 按查詢，顯示城市、IANA 時區、座標、B 時刻的當地時間、剩餘時間及到達 A 時的台灣時間。

A、B 格式皆為 `YYYYMMDD HH:MM`。A 是每座城市的當地時間；手動 B 固定視為台灣 UTC+8，不受電腦時區影響。目前時間模式在按查詢時讀取電腦時鐘。

查詢範圍為 B 至 B＋60 分鐘，包含兩端，不向下取整點。比對完整年月日，已過期或超過一小時的目標不列出。透過瀏覽器 Intl 時區資料處理夏令時間；不存在的當地時間不列出，重複時間會依實際到達時刻列出。只搜尋內建城市清單，不是全球所有座標。

## 範例

A：`20260923 11:00`；B：`20260923 09:53`（台灣時間）。

涉谷當地為 `20260923 10:53`，7 分鐘後到達 A，因此列出：

```text
涉谷（Asia/Tokyo）
座標：35.658863, 139.700918
B 時刻的當地時間：20260923 10:53:00
7 分 0 秒後到達 A；到達時的台灣時間：20260923 10:00:00
```

東京也會符合。台北需等 67 分鐘，因此不列出。

## 上傳至 GitHub

執行 `BAT/03_push_to_github.cmd`。腳本從自身位置定位專案，提交所有變更並推送目前分支；沒有新變更時仍會推送尚未上傳的提交。失敗時會保留錯誤訊息，不會顯示成功。

到 GitHub 儲存庫選取腳本顯示的分支。腳本位於 `BAT` 資料夾，不在根目錄。上傳程式碼與發布網站是不同步驟；若需網站，可在儲存庫的 Pages 設定選擇要發布的分支與根目錄。

純前端，不使用 API 或資料庫，可直接開啟或部署至 GitHub Pages。
