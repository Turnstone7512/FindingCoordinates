# FindingCoordinates

指定時間 A（各城市當地日期時間），以 B 為基準，查詢未來 60 分鐘內會到達 A 的內建城市與座標。

## 使用方式

1. 開啟 `index.html`，以日曆選擇 A 的日期，例如 `2026-09-23`，並從下拉選單選擇小時 `11`。
2. B 可選「目前台灣時間」或手動選擇台灣日期與小時，例如 `2026-09-23`、`09`。
3. 按查詢，依到達 A 時的台灣時間分組，顯示城市、IANA 時區與座標。小時為橘色，座標為藍色；座標右側可單筆複製，上方可複製全部結果。

A 與手動 B 均使用日期選擇器、小時下拉選單（0～23），分鐘固定為 `00`；目前時間模式保留即時的分與秒。A 是每座城市的當地時間；手動 B 固定視為台灣 UTC+8，不受電腦時區影響。目前時間模式在按查詢時讀取電腦時鐘。

查詢範圍為 B 至 B＋60 分鐘，包含兩端，不向下取整點。比對完整年月日，已過期或超過一小時的目標不列出。透過瀏覽器 Intl 時區資料處理夏令時間；不存在的當地時間不列出，重複時間會依實際到達時刻列出。只搜尋內建城市清單，不是全球所有座標。

## 範例

A：`20260923 11:00`；B：目前台灣時間為 `20260923 09:53`（使用目前時間模式）。

涉谷當地為 `20260923 10:53`，7 分鐘後到達 A，因此列出：

```text
台灣時間：20260923 10:00

涉谷（Asia/Tokyo）
35.658863, 139.700918
```

東京也會符合。台北需等 67 分鐘，因此不列出。

## 上傳至 GitHub

執行 `BAT/03_push_to_github.cmd`。腳本從自身位置定位專案，提交所有變更並推送目前分支；沒有新變更時仍會推送尚未上傳的提交。失敗時會保留錯誤訊息，不會顯示成功。

到 GitHub 儲存庫選取腳本顯示的分支。腳本位於 `BAT` 資料夾，不在根目錄。上傳程式碼與發布網站是不同步驟；若需網站，可在儲存庫的 Pages 設定選擇要發布的分支與根目錄。

純前端，不使用 API 或資料庫，可直接開啟或部署至 GitHub Pages。

## 驗證

安裝 Node.js 後執行 `node --test app.test.js`。

若 B 早於所有內建城市到達 A 的時間，而且未來一小時內沒有結果，會直接顯示最早到達 A 的台灣時間與所有同時到達的城市。最早城市依 A 當日的時區（含夏令時間）判斷，不固定使用清單第一筆；若已有城市到達 A，仍使用原本的一小時範圍。

時間 A 的日期與小時會在變更時自動儲存於瀏覽器 localStorage，下次開啟同一網站時還原（分鐘固定 00）。沒有有效紀錄時使用目前台灣日期與小時；時間 B 不儲存。
